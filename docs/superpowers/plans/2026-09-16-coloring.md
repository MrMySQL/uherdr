# uherdr Coloring Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Adopt upstream Herdr's existing themes, color overrides, and sidebar coloring rules in uherdr.

**Architecture:** Resolve appearance in a single app-owned store, then pass immutable UI palette values into SwiftUI and retained terminal hosts. Import local Herdr configuration through a read-only adapter; native controls expose the same upstream coloring semantics, while existing terminal palettes remain unchanged.

**Tech Stack:** Swift, Foundation, SwiftUI, AppKit, GhosttyTerminal, Swift Package Manager; pinned TOMLKit 0.5.0 for configuration import.

**Spec:** `docs/superpowers/specs/2026-09-16-coloring-design.md` — read it before execution. Implementation was authorized and delivered task-by-task. The broad whole-branch review at `c183a4c` found no blocking issues, and its three minor follow-ups have been applied. Task checkboxes record implementation evidence, not an unrestricted compatibility claim.

**Acceptance limits:** installed Swift 6.4/SDK 26.5 and Herdr 0.9.0 were tested; Swift 6.0/macOS 14 remain documented requirements, not tested versions in this environment. Newer optional metadata uses public-schema fixtures, not a newer binary capture. Visual evidence is native AppKit view-cache rendering, including explicit high-contrast appearances; desktop capture and a live system-wide Increase Contrast toggle are not claimed. See `docs/verification.md`.

## Global Constraints

- Keep macOS 14 as the minimum platform and Swift 6.0 as the documented build requirement.
- Keep Herdr 0.9.0 as the base runtime requirement; newer metadata is optional and capability-dependent.
- Keep GhosttyTerminal as the terminal renderer; use its existing configuration APIs without vendor edits.
- Store native appearance preferences locally; do not modify Herdr config files or remote machines.
- A color change must not recreate a terminal, restart a shell, acquire a new writable controller, or discard scrollback.
- Preserve retained-tab behavior: hidden tabs receive cosmetic changes before reveal, without continuous hidden-view publication.
- Preserve the current appearance until the user selects a theme or imports settings.
- Adopt only upstream-supported coloring semantics; add no individual resource colors or terminal palette customization.

## Task 1: Color values, palettes, and resolution

**Create:** `Sources/HerdrCore/Appearance/ColorValue.swift`, `ThemePalette.swift`, `ThemeResolver.swift`, `BuiltInThemes.swift`; `Tests/HerdrCoreTests/AppearanceTests.swift`; `docs/theme-provenance.md`.

**Modify:** `Tests/HerdrCoreTests/ProtocolTests.swift` to invoke `try AppearanceTests.run()`.

**Interfaces:** Foundation-only, `Codable`, `Equatable`, and `Sendable` values. Define these contracts before their consumers:

```swift
public enum AppearanceMode: String, Codable, Sendable { case system, light, dark }
public enum ThemeVariant: String, Codable, Sendable { case light, dark }
public enum ColorValue: Codable, Equatable, Sendable {
    case rgb(UInt8, UInt8, UInt8)
    case reset
    public static func parse(_ text: String) throws -> ColorValue
}
public typealias ThemeOverrides = [String: ColorValue]
public struct ThemePalette: Codable, Equatable, Sendable {
    public var colors: ThemeOverrides
}
public enum ThemeResolver {
    public static func resolve(base: ThemePalette, layers: [ThemeOverrides]) -> ThemePalette
}
```

Add public initializers for externally constructed structs. `resolve` merges layers in order; `.reset` restores that role's base/native fallback, not the previous custom layer. After normalization every semantic role has a usable value. Add `BuiltInThemes.palette(named:variant:) throws -> ThemePalette` and a sorted public name list.

## Plan review

The six-task plan covers upstream themes, mode switching, supported color overrides, conditional sidebar text styles, migration, live UI updates, device-specific metadata, and validation. Global theme/rule settings persist locally. Individual resource colors, inheritance, per-pane backgrounds, and new terminal palette controls are excluded. No runtime changes, config-file writes, automatic file watcher, or cross-machine preference synchronization are required.
